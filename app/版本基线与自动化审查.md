# 1.5 版本基线与自动化审查

本次以 1.4.3 实际发布 EXE 中的代码归档为依据，不依据旧版本号命名的源码目录推定版本。审查脚本为 `tools/audit_143_baseline.py`，机器可读结果为 `.planning/ui-1.5/automation-baseline-audit.json`。

## 开发来源与范围

1.5 开发目录实际从现有 1.4.9 源码复制，随后核对 1.4.3 发布包并进行界面调整。此前未明确告知这个来源，不应把它描述成“直接基于完整 1.4.3 源码、仅换界面”。

两者不是所有代码均相同：1.4.9 有宿舍登录调查相关代码和浏览器辅助修改；1.5 还包含用户指定的无线无浏览器优先、浏览器后备策略。1.5 隐藏并禁用了宿舍调查入口和观察配置，但没有从磁盘和发布包中彻底移除这些模块。上述事实与“实际启用调查功能”应区分。

## 自动化核对结果

| 核对项 | 1.4.3 实际发布包 | 1.5 修正后 |
| --- | --- | --- |
| 开机开关 | 开机后自动联网 | 保留原文案及独立配置 |
| 唤醒开关 | 每天定时唤醒 | 已恢复原文案；此前重排界面时误改成每天唤醒并联网 |
| 休眠开关 | 每天定时休眠 | 保留 |
| 顶部下次任务提示 | 唤醒并联网 | 沿用；这句话原版已有 |
| 配置保存 | 分别保存开机、唤醒开关 | 仍分别保存 |
| 计划任务安装 | 分别控制 Monitor 与 Wake | 整个 scheduler 模块与 1.4.3 语义一致 |
| 唤醒协调与后台恢复 | 唤醒后交接联网请求，由唯一监测进程检查并按需恢复 | 关键函数与 1.4.3 语义一致 |

“开机后自动联网”实际指登录 Windows 后按当前模式自动联网，不会自行唤醒电脑。“每天定时唤醒”控制设定时刻的唤醒任务；1.4.3 的这个任务并不是只唤醒硬件就结束：它会向后台监测投递联网确认请求。已在线时不重复认证，离线时进入恢复流程，即使开机联网开关关闭也可独立触发。

因此两个选项的触发时机不同，但后续联网恢复流程存在交集。这是 1.4.3 的原行为，不能通过本次界面修改悄悄改变。用户记得的开关名称是正确的；把名称改成“每天定时唤醒”不等于底层功能被改为“仅唤醒、不检查联网”。

## 精确比较与修正

逐个比较实际 1.4.3 包内代码对象与当前源码，排除文件路径、行号等编译位置差异，包含指令、常量、参数和异常表。结果确认：

- `scheduler.py`、`monitor_state.py`、`startup.py`、`wake_coordination.py` 整个模块语义一致。
- `run_wake_coordinator`、`_process_wake_request`、`_monitor_locked`、`run_morning` 与 1.4.3 语义一致。
- `update_schedule_controls`、`update_schedule_hint` 与 1.4.3 语义一致。
- `update_next_action` 在 1.5 改为读取已应用配置，原版读取编辑中的控件值；这是显示差异，任务调度未变。
- `configure_and_install` 的差异包括强制无线无浏览器优先、关闭宿舍观察；开机和唤醒仍为两个独立字段。

本次运行时代码仅修改 `ui_layout.py`：恢复“每天定时唤醒”，添加说明其沿用原版唤醒后联网检查与恢复流程的悬浮提示。使用说明同步修正工位检查入口名称。未修改调度、唤醒、认证、保活或恢复逻辑。

补充隔离测试覆盖：开机开关开启或关闭都不影响启用后的每日唤醒交接；唤醒时已在线不重复认证，离线才请求恢复；界面两开关互不联动。所有测试模拟网络、任务和请求存储，不执行真实认证或安装计划任务。发布包校验不等同于真实冷启动或定时唤醒实测。

最终验证：330 项隔离回归全部通过；20 张模拟状态界面截图已生成并查看自动化页；169 条目发布包完整性、说明同步、桥接自检和界面启动检查通过。修正版仍为 1.5，构建目录 `dist-builds/20261017-104940`，ZIP SHA-256 为 `998fb8a7fdbb2eed4a5f70efbf47c0a2d37b6c3ae318fd0166fe45ed9e4bc996`。未替换正在使用的桌面程序。
